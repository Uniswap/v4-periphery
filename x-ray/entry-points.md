An important structural note: `MarginRouter` inherits `MarginAccountFactory`, `Multicall_v4`,
`Permit2Forwarder`, `NativeWrapper`, `ReentrancyLock`, and `V4Router`. Several inherited functions
are part of the router's live external surface even though they are not declared in
`MarginRouter.sol`. They are listed below because an entry-point inventory that only reads the
top-level file would miss them.

`execute` deserves separate emphasis. It is the only entry point that runs a caller-authored opcode
plan, and it deliberately enforces no slippage, health, or fill bounds and makes no zero-residual
guarantee. The [interface documents eight composition rules](../src/interfaces/IMarginRouter.sol#L296)
the caller must satisfy, including that signing a plan is strictly worse than granting a token
approval. Auditors should treat the eight rules as the specification and look for ways a plan can
escape the caller's own account scope, not for ways an unsafe plan can lose the caller's own money.

`createAccount` being permissionless with an arbitrary `owner` argument is worth a deliberate
verdict rather than an assumption. The CREATE2 salt binds `(owner, manager, subId)`
([L80-82](../src/MarginAccountFactory.sol#L80)) and the immutable args bake in `(owner, manager)`
([L70-72](../src/MarginAccountFactory.sol#L70)), so a third party deploying at a victim's predicted
address produces a clone owned by the victim. The apparent squat is self-defeating. It is listed
here so that the reasoning is recorded, not because it is presumed exploitable.

### Action opcodes reachable inside an unlock

Dispatched by [`_handleAction`](../src/MarginRouter.sol#L505) across three ranges. Every
account-scoped opcode reads the active account from transient storage and never from calldata.

| Opcode | Value | Allowlist gated | Active account required | Notes |
|---|---|---|---|---|
| `SET_ACCOUNT` | 0x37 | no | no (it sets it) | Derives the account from `msgSender()` + decoded `subId`. |
| `ASSERT_FILL` | 0x36 | no | no | Reads the router's own swap credit via `_getFullCredit`. |
| `ACCOUNT_SUPPLY_COLLATERAL` | 0x30 | **yes** | yes | Exposure-increasing. |
| `ACCOUNT_BORROW` | 0x32 | **yes** | yes | Exposure-increasing. |
| `ACCOUNT_WITHDRAW_COLLATERAL` | 0x31 | no | yes | Ungated so a position stays exitable. |
| `ACCOUNT_REPAY` | 0x33 | no | yes | Ungated. |
| `ACCOUNT_SWEEP` | 0x34 | no | yes | Recipient constrained by the account. |
| `ASSERT_HEALTH` | 0x35 | no | yes | **A zero bound skips the check entirely.** |
| `PULL_TO_ACCOUNT` | 0x38 | no | yes | `0` amount reverts; `CONTRACT_BALANCE` honored only on the router-balance path. |
| `SWEEP` / `WRAP` / `UNWRAP` | 0x14-0x16 | no | no | Intercepted from the core `Actions` range with PositionManager-identical semantics. |
| swap / settle / take opcodes | `< SWEEP` | no | no | Fall through to inherited `V4Router._handleAction`. |

## MarginAccount (one clone per `(owner, subId)`)

Ownership is soulbound: `(owner, manager)` are baked into the clone bytecode as Solady immutable
args and read via `LibClone.argsOnClone`
([L145-147](../src/MarginAccount.sol#L145)). There is no initializer to front-run and no transfer
path.

| Function | Access | Recipient constrained | Notes |
|---|---|---|---|
| [`supplyCollateral`](../src/MarginAccount.sol#L47) | manager or owner | n/a | Approves the protocol for `amount`, calls, resets approval to 0. |
| [`withdrawCollateral`](../src/MarginAccount.sol#L68) | manager or owner | **yes** — manager or owner | Forwards the measured balance delta; delta is 0 when the protocol delivered directly. |
| [`borrow`](../src/MarginAccount.sol#L89) | manager or owner | **yes** — manager or owner | Always borrows to itself, then forwards the measured delta. |
| [`repay`](../src/MarginAccount.sol#L107) | manager or owner | n/a | `type(uint256).max` approves the full balance; approval reset to 0. |
| [`sweep`](../src/MarginAccount.sol#L120) | manager or owner | **yes** — manager or owner | Moves a raw token balance out. |
| [`execute`](../src/MarginAccount.sol#L128) | **owner only** | no | Forwards arbitrary calldata + `msg.value` to a **caller-supplied** `adapter.lendingProtocol()`. The manager cannot reach this. |
| [`receive()`](../src/MarginAccount.sol#L187) | anyone | n/a | Unguarded native fallback. |
| `owner()`, `manager()` | view | — | — |

The recipient constraint is the account's central safety property: authority-bearing fields are
owned and re-validated by the account rather than trusted from adapter-encoded bytes
([`_requireReceiver`, L163-165](../src/MarginAccount.sol#L163)). Note that "manager" is an
allowed recipient, which means funds can legitimately land on the router mid-flow. Whether that
router balance is always attributable to the correct caller is the highest-value question this
inventory raises.

## Lending adapters

All four adapters expose the same shape: a governed market registry plus `OwnableAdapter`'s
two-step ownership. Every `encode*` and read function is `view` and reverts for an unrouted pair,
so the only state-changing surface is market curation and the ownership handoff.

| Contract | Owner-only | Permissionless | Registry validation on enable |
|---|---|---|---|
| [`MorphoLendingAdapter`](../src/MorphoLendingAdapter.sol#L230) | `setMarket(MarketParams)`, `transferOwnership` | `acceptOwnership` | Market must exist on Morpho Blue (`idToMarketParams(id).loanToken != 0`). |
| [`AaveLendingAdapter`](../src/AaveLendingAdapter.sol#L261) | `setMarket(Currency,Currency,bool)`, `transferOwnership` | `acceptOwnership` | Both assets must be live Aave reserves (non-zero aToken). |
| [`AaveV4LendingAdapter`](../src/AaveV4LendingAdapter.sol#L294) | `setMarket(Currency,Currency,uint256,uint256,bool)`, `transferOwnership` | `acceptOwnership` | Each reserve's `underlying` must match the registered currency; both reserves must share a Hub. |
| [`CompoundV3LendingAdapter`](../src/CompoundV3LendingAdapter.sol#L285) | `setMarket(Currency,Currency,bool)`, `transferOwnership` | `acceptOwnership` | `debt` must equal `comet.baseToken()`; collateral must be a registered Comet collateral asset. |

Note the asymmetry between adapters in what happens when a market is **disabled**. The Aave v4
adapter deletes the route ([L318](../src/AaveV4LendingAdapter.sol#L318)); the Aave v3 and Compound
adapters flip a boolean; the Morpho adapter's `MarketRegistry` has no removal path at all
([`register` only overwrites](../src/types/MarketRegistry.sol#L36)). Since every adapter read and
encode reverts for an unrouted pair, de-registering a market that has open positions is a
candidate liveness problem, and the three adapters would fail differently. This is routed to the
invariant lens as the EXITABILITY question.
